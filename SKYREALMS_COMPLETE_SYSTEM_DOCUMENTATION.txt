1. SYSTEM OVERVIEW & ARCHITECTURAL PHILOSOPHY
====================================================================================================
SkyRealms is an enterprise-grade Minecraft SkyBlock server platform engineered with a modular
monolith design pattern. Each domain (Player, Economy, Islands, Farming) is encapsulated in an
independent, hot-deployable Paper plugin JAR while sharing contracts via platform API modules.

Key Architectural Principles:
1. Zero Vanilla Client Dependencies: The entire server experience (custom crops, interactive GUIs,
   custom items, celestial holograms, divine cinematics, multi-currency banks, and mastery perks)
   runs strictly on vanilla Paper 1.21.1 packets. No Forge, Fabric, NeoForge, custom launchers, or
   mandatory resource packs are ever required.
2. Direct Acyclic Graph (DAG) Lifecycle: Plugin modules declare strict dependencies. On boot,
   the Core module topologically sorts and enables modules in dependency order (Database -> Player ->
   Economy -> Islands -> Farming). On shutdown, modules disable in exact reverse dependency order.
3. Decoupled Service Registries: Plugins expose public APIs through Bukkit's ServicesManager and
   SkyRealms's internal ConcurrentServiceRegistry, eliminating tight coupling between plugins.
4. Resilient Multi-Driver Database Abstraction: Seamless production connection to PostgreSQL with
   automatic local development fallback to embedded H2 in PostgreSQL compatibility mode.

2. MODULE DEPENDENCY GRAPH & RUNTIME LIFECYCLE
====================================================================================================

Compilation & Runtime Graph:
  [platform:api]
       ^
       |--- [platform:common]
       |--- [platform:database-api]
       |--- [platform:integrations-api]
       |--- [platform:testing]
       |
       v
  [SkyRealmsCore] (Classloader host & DAG Coordinator)
       |
       +--> [SkyRealmsDatabase] (Database & Flyway service)
                 |
                 +--> [SkyRealmsPlayer] (Profile persistence)
                           |
                           +--> [SkyRealmsEconomy] (Coins & Gems, Vault)
                                     |
                                     +--> [SkyRealmsIslands] (SkyBlock Islands)
                                               |
                                               +--> [SkyRealmsFarming] (Garden & Mastery)

DAG Initialization Order:
  1. SkyRealmsCore: Bootstraps runtime, initializes ServiceRegistry, EventBus, ModuleRegistry.
  2. SkyRealmsDatabase: Connects HikariCP pool, validates & executes Flyway migrations (V1-V6).
  3. SkyRealmsPlayer: Hooks connection listeners, activates profile caching.
  4. SkyRealmsEconomy: Registers Vault economy provider, loads active currencies.
  5. SkyRealmsIslands: Creates void world 'skyrealms_islands', populates spatial allocation grid.
  6. SkyRealmsFarming: Creates void world 'skyrealms_garden', auto-heals plots, loads active gardens.

- module/ModuleLifecycleManager.java: Contract for enabling/disabling module DAGs.
- service/ServiceRegistry.java: Decoupled service locator for cross-plugin API retrieval.

B. platform:common (C:\servermc\skyrealms\platform\common\)
   Authoritative implementations of the core platform abstractions.
----------------------------------------------------------------------------------------------------
- command/DynamicCommandRegistrar.java: Dynamic runtime Bukkit command injector (bypasses plugin.yml).
- event/DefaultEventBus.java: Thread-safe, priority-sorted event dispatcher.
- module/DefaultModuleContext.java: Standard implementation of ModuleContext.
- module/DefaultModuleRegistry.java: Thread-safe ConcurrentHashMap module registry.

Package: com.skyrealms.core

coordinates the DAG lifecycle, boots all modules on server startup, and safely shuts them down on stop.

Key Files:
1. SkyRealmsCorePlugin.java:
   - Extends JavaPlugin.
   - Instantiates DefaultEventBus, ConcurrentServiceRegistry, and DefaultModuleRegistry.
   - Listens for server load completion to trigger ModuleLifecycleManager.enableAll().
   - Shuts down active modules in reverse order on onDisable().
2. module/CoreModule.java:
   - Core SkyModule implementation representing the SkyRealms platform kernel.
   - Registers core services and exposes the base system status.
3. command/SkyRealmsCommand.java:
   - Primary administrative command: /skyrealms (aliases: /sr).
   - Subcommands: /sr status, /sr reload, /sr modules, /sr dump.

Package: com.skyrealms.database

High-performance database connectivity layer backed by HikariCP. Manages automatic failover between
PostgreSQL and embedded H2, and executes versioned Flyway database migrations (V1 to V6).

Key Files:
1. SkyRealmsDatabasePlugin.java:
   - Extends JavaPlugin. Registers the "database" module with SkyRealmsCore.
2. module/DatabaseModule.java:
   - Implements SkyModule.
   - Attempts initial connection to PostgreSQL at 127.0.0.1:5432.
   - If unreachable, gracefully falls back to local embedded H2 in PostgreSQL compatibility mode:
     jdbc:h2:C:/servermc/plugins/SkyRealmsCore/modules/database/skyrealms_dev;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE
   - Runs Flyway migrations from classpath:db/migration.
   - Registers DatabaseService in Bukkit ServicesManager.
3. HikariDatabaseService.java:
   - Implementation of DatabaseService using HikariDataSource.
   - Provides getConnection(), executeTransaction(callback), executeTransactionVoid(action).
4. migration/DatabaseMigrationService.java:
   - Encapsulates Flyway configuration, baseline, validation, and migration execution.

  - sr_island_upgrades (island_id UUID, upgrade_type VARCHAR(64), level INTEGER, PK (island_id, upgrade_type))

V4__create_farming_tables.sql:
  - sr_farming_progress (player_uuid UUID PK, farming_level INT, farming_xp BIGINT, ...)

  - sr_farming_generators (generator_id UUID PK, island_id UUID, tier VARCHAR(32), ...) [LEGACY/RETIRED]

V5__create_garden_tables.sql:
  - sr_gardens (garden_id UUID PK, island_id UUID UNIQUE FK, region_index INT UNIQUE, center_x, center_z, ...)
  - sr_garden_plots (island_id UUID FK, plot_index INT (1-16), unlocked BOOLEAN, crop_type, PK (island_id, plot_index))
